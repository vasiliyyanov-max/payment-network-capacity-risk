# Payment Network Capacity Risk & Early Warning — v7

Синтетический проект. Денежные суммы — условные единицы.

## Состав
- `capacity_core.py` — общее ядро: конфигурация, эпизоды тревог, оценка порогов, экономика, бутстрап. Пайплайн и дашборд используют одни и те же функции.
- `run_capacity_pipeline.py` — симуляция, признаки, модели, калибровка, подбор порогов, оценка на тесте. Результаты — в `capacity_output/`.
- `dashboard_capacity.py` — дашборд Streamlit на RU / EN / UK. Читает только файлы пайплайна; «что если» пересчитывается через ядро.
- `capacity_output/` — результаты последнего прогона (seed 20251029).

## Запуск
```bash
pip install numpy pandas scikit-learn streamlit plotly
python run_capacity_pipeline.py     # около 15 секунд, создаёт capacity_output/
streamlit run dashboard_capacity.py
```

## Сценарий решений
В пайплайне задан стресс в двух каналах: COMP-06 — нарастание нагрузки без перегрузки, COMP-04 — нарастание, которое переходит в перегрузку. Расписание задаётся в `SCENARIO_SCHEDULE` (run_capacity_pipeline.py). Состояния Review и Restrict не задаются: они появляются из обученной модели и порогов. Дашборд показывает три политики на одном сценарии: без системы, только Review, Review + Restrict, и журнал решений с действиями и результатами.

## Что изменилось в v7.1
- Полезность эпизода считается по всему эпизоду (от первого часа до последнего часа + горизонт), а не только по его началу. Раньше эпизод, который переходил в Restrict, ошибочно считался ложным.
- Сценарная логика вынесена в ядро (`scenario_policies`), поэтому дашборд пересчитывает сценарий с текущими порогами и стоимостями.
- Переключатель языка: «Language / Мова / Язык».

## Что изменилось относительно v6
- Все метрики и экономика вычисляются, ничего не захардкожено. Дашборд без результатов не показывает выдуманных значений.
- Исправлена разметка событий: события имеют реальную длительность, а не длину в 1 час.
- Пороги Review и Restrict подбираются по чистому эффекту на отдельном блоке; тест в подборе не участвует.
- Добавлены базовые модели (константа, эвристика по очереди, логистическая регрессия), сравнение по ROC-AUC, PR-AUC, Brier skill и по событийным метрикам.
- Экономика учитывает уровень реакции, фиксированную стоимость эпизода и почасовую стоимость мониторинга.
- Введено ограничение на долю часов в режиме тревоги: без него «тревога, которая не выключается» давала recall 100%.
- Бутстрап-интервалы для полноты, запаса, полезности, чистого эффекта и ROI.
- Исправлена формула стоимости и синтаксические недочёты дашборда.

## Ограничения
- Restrict срабатывает у верхней границы калиброванного риска (около 0.44–0.45), поэтому в сценарии он длится считанные часы до перегрузки.
- Review на каналах без стресса — ложные тревоги; они попадают в журнал и в экономику.
- Связь «ограничение счёта → перегрузка сети» не моделируется.
- Синтетический мир стационарен: PSI почти всегда стабилен.
- Выборка событий на тесте мала, интервалы широкие.
- Калибровка в низком диапазоне вероятностей неточная.
